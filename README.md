# 칠성 미러마켓

## 콘텐츠 트렌드 · 자동 관측

기본 화면 **콘텐츠 트렌드**에서 관측을 시작한다. 기존 공개 수집기 → Decode 저장/관측 이력 → Laya 포맷 분류 → BERTopic 주제 탐색 → AI 음식·장르·테마 해석이 자동으로 이어진다. **식료품·음식·음료·주류**만 대상으로 한다. 수집 검색어와 후보 규칙 → Laya 식음료 중심 주제 판정(선택 확률 0.75 이상) → 분야 분류를 거치며, 범위 밖·미분류·판단이 애매한 글은 그래프와 BERTopic에서 제외한다. 기존 원본과 타 캠페인은 삭제하지 않는다. 이 기준은 정확도 보증이 아니며 일부 관련 글이 누락될 수 있다. **Jev·Apify 실행 경로는 없다.**

```bash
.venv/bin/pip install -r requirements.txt -r requirements-decode.txt
.venv/bin/streamlit run app.py
# UI를 열지 않고 지속 수집할 때
.venv/bin/python -m mirror.trends watch
# 진행 중인 배치 저장 후 중지
.venv/bin/python -m mirror.trends stop
```

- **음식·브랜드 / 음식 장르 / 소비 테마**에서 최근 신호와 과거 인기를 나눠 본다. AI가 원문에 실제 있는 음식명과 근거 구절을 추출하고, 공개 지표·작성자 수·재관측 이력이 순위를 결정한다. 항목을 누르면 근거 게시물과 그래프를 함께 좁힌다. 조회·좋아요·댓글·공유 누락값은 그대로 둔다.
- **주제 지도 / 급상승 / 조회·반응 / 소스 확산 / 카드**로 탐색한다. 점이나 카드를 누르면 원문, 분류, 실제 관측 지표와 최근 조회수 이력을 본다. 필터와 선택은 5초 화면 갱신 중에도 유지된다.
- 공개 커뮤니티·RSS·뉴스·구글 트렌드·블루스카이·마스토돈의 식음료 자료는 최소 10분, 필수 소셜 4채널은 1시간 간격으로 관측한다. 화면 상태는 5초마다 갱신하며 수집 주기와 구분한다. YouTube는 키 없는 공개 검색(yt-dlp) 또는 `YOUTUBE_API_KEY` 공식 검색을 사용한다. 공개 검색은 음식·음료·맛집·주류 4개 검색어 × 8개 결과 중 후보를 저장하며, 각 검색 상위 2개만 상세 반응을 조회한다. 소스별 성공·부분 수집·실패·설정 필요와 실제 이벤트가 보인다.
- 수집 워커는 파일 잠금으로 하나만 실행된다. 창을 닫아도 실행되지만 **컴퓨터가 깨어 있고 프로세스가 살아 있어야 한다**. 재부팅 후 화면의 관측 시작으로 다시 켠다. 중단된 작업은 저장한 분류와 임베딩부터 재개한다.
- 조회·재생 증가량은 같은 지표를 두 번 이상 관측했을 때만 계산한다. 조회수가 공개되지 않은 콘텐츠는 별도로 좋아요 증가량을 계산하며, 조회 증가율과 섞어 비교하지 않는다. ‘급상승’은 같은 소스/플랫폼/지표에 유효 증가율이 5개 이상 있을 때 상위 20%이며 증가량이 양수인 콘텐츠다. 세 번째 관측부터 이전 구간 대비 속도 변화도 표시한다. 게시 후 시간, 계정 규모나 광고 노출을 보정한 미래 바이럴 확률은 아니다.
- 소스 확산은 **같은 주제의 소스별 최초 발견 시각**이다. 인과관계·원조·실제 전파 경로를 주장하지 않는다. 새로운 글 수는 게시 시각이 아닌 최초 수집 시각 기준이다.
- BERTopic은 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`의 로컬 ONNX 임베딩과 UMAP, HDBSCAN, c-TF-IDF를 사용한다. 최근 7일 재관측 자료 중 최신 3,000건을 묶으며, 모델은 제목·본문·대본 앞 128토큰을 읽는다. 표본 10건 미만은 대기, 잡음(-1)은 별도 트렌드로 세지 않는다. 주제 ID는 중심 벡터 유사도 0.82 이상일 때 일대일 연결한다. 이 임계값과 주제 이름은 운영 가정이며 정확도 보증이 아니다.
- Laya는 로컬 체크포인트 `data/models/laya-ko`를 사용하고, GPU가 있으면 CUDA/MPS를 사용한다. 내용/분류 기준이 달라진 콘텐츠만 다시 분류한다. 영상 파일 URL이 제공된 자료의 Whisper/OCR도 자동 연결된다. 직접 영상 URL이 없는 영상은 캡션과 제공된 대본으로 분석한다.
- YouTube·Instagram·TikTok·Threads를 상단에 고정 표시한다. 실제 상태·식음료 콘텐츠 수·공개 조회수 수를 구분하고, 플랫폼·식음료 분야·롯데칠성 취급 브랜드/경쟁 카테고리 필터를 제공한다. 네 채널 모두 계정 없이 공개 수집이 기본이다. 공개 수집과 선택적인 공식 API 커넥터, 지정 게시물 재관측을 지원한다. 조회수가 없는 Threads는 좋아요·댓글 그래프와 좋아요 증가 속도를 표시한다. 채널별 실제 수집 경로·분류 대기·부분 실패를 구분한다. JSON/CSV로 가져온 식음료 자료도 다음 주기에 연결한다. 공개되지 않은 지표는 ‘—’로 두고 포인트·재게시를 조회수로 바꾸지 않는다. 인터넷 전체의 무제한 실시간 수집을 의미하지 않는다.

상태·이벤트·임베딩 캐시는 `data/decode.db`, 로그는 `data/trend-worker.log`, 다국어 모델 캐시는 `data/models/topics`에 저장한다. 기존 원본과 캠페인은 보존한다. `python -m mirror.media collect/watch`와 `python -m mirror.formats collect`도 수집 후 자동 분석을 연결한다. 실행 중인 관측 워커가 있으면 그 워커가 다음 주기에 연결한다. 기본 수집 주기는 작업 완료 후 10분이며, 초기 누적 분류가 많을 때 첫 주기가 길어질 수 있다.

검증: ` .venv/bin/python -m unittest discover -s tests -v` (외부 수집은 모의 응답, BERTopic 한국어 군집은 실제 라이브러리 실행).

### 계정 없는 소셜 자동 수집

네 채널 모두 키·로그인 없이 시작한다. 기존 Decode 저장 → 로컬 Laya 식음료 분류 → BERTopic 주제 탐색으로 자동 연결하며, 실제 공개 응답의 카운터만 기록한다. 일반 HTTPS 탐색 요청과 페이지에 포함된 JSON을 읽는다. 개인 쿠키·비공개 API·CAPTCHA 처리·유료 프록시·Apify는 사용하지 않는다. 새 패키지 의존성도 없다.

| 채널 | 기본 발견 경로 | 공개 지표와 범위 |
|---|---|---|
| YouTube | yt-dlp 식음료 공개 검색 | 4검색어 × 8개, 검색 상위 2개씩 상세 반응. 관련도순이며 게시 시각과 발견 시각 구분 |
| Instagram | `/popular/<키워드>/` 공개 인기 검색 → shortcode가 같은 원문 | 검색당 최대 12개, 작성자당 최대 2개. 공개 검색의 실제 재생수와 원문의 캡션·게시일·좋아요·댓글을 결합. 상세 접근 실패 시 검색 본문·재생수만 보존하고 나머지는 미확인 |
| TikTok | 네이버의 `site:tiktok.com <키워드>` 공개 검색 → 영상 원문 JSON | 검색 링크 중 최대 12개 새 원문 확인, 작성자당 최대 2개. 실제 원문의 조회수·좋아요·댓글·공유·게시일. 검색 요약 수치를 카운터로 사용하지 않음 |
| Threads | 공개 키워드·해시태그 검색 | 검색당 첫 20개 미리보기. 검색 결과의 직접 게시물만 추출하고 중첩 인용은 제외. 좋아요·댓글·재게시·공유; 조회수 미공개. 익명 페이지 넘김·최신순 보장 없음 |

고정 계정 목록은 기본 수집에서 제거했다. `trend_discovery.py`의 식음료 탐색어 32개에서 시작하며 플랫폼당 매회 8개를 순환한다. **소셜 주기는 1시간, 같은 검색어의 재검색은 최소 6시간**이다. 플랫폼이 제공한 식음료 연관어와 AI가 여러 작성자에서 확인한 음식명을 큐에 추가한다(플랫폼당 최대 200개). 신규·학습 검색어는 매회 최대 2개를 예약해 초기 탐색어도 계속 순환한다. 실제 검색어·상태·발견 수·공개 본문 확인 수·출처가 화면에 보이며 발견 수를 유행 지표로 사용하지 않는다.

목록 밖으로 밀려난 글도 최근 7일 관측 자료에서 오래 관측한 20개씩 원문을 갱신한다. **공개 수집 범위·링크 추가**에서 특정 게시물 URL을 추가하면 주기당 채널별 5개씩 별도 확인한다. 삭제된 글이 홈으로 이동하거나 요청한 ID와 다른 응답이면 실패 처리한다. 실패 때 기존 자료는 보존하고 새 관측값을 만들지 않는다.

`trend_insights.py`는 기존 `consumer.chat`과 프로젝트의 `GEMINI_API_KEY` 설정을 재사용한다(`gemini-3.5-flash-lite`). **소셜 수집에는 계정·API가 필요 없지만 이 추가 해석은 설정된 AI API를 사용한다.** Laya를 통과한 4개 소셜의 본문 최대 1,800자를 읽어 음식명·장르·테마를 추출한다. 실제 본문에 없는 음식명과 근거 구절은 버린다. 8건씩, 한 분석 주기 최대 400건이며 본문과 해석 버전으로 캐시한다. 형식 오류는 1회 재시도하고 성공한 배치는 바로 저장한다. AI 오류가 나도 로컬 분류·주제·지표는 유지한다.

- 최근 신호는 30일 이내 게시물 또는 15분 이상 간격의 실제 조회·좋아요·공유 증가다. 옛 인기글을 방금 발견했다는 이유만으로 최근 유행으로 올리지 않는다.
- 반응 백분위는 플랫폼·게시 연령(7일/30일/이전/미확인)별로 지표가 있는 5건 이상을 비교한다. 조회·재생은 같은 종류만 비교하며 좋아요·댓글·공유의 백분위를 평균한다. 0·미공개는 점수 근거로 올리지 않는다.
- 최근 콘텐츠의 작성자 3명 이상·평균 백분위 70 이상이면 ‘최근 인기 후보’, 실제 증가가 확인된 콘텐츠 2건 이상이면 ‘증가 확인’이다. 한 작성자의 반복 게시만으로 유행을 확정하지 않는다. 임계값은 운영 기준이며 전 플랫폼의 공식 순위나 바이럴 확률이 아니다.

2026-11-24 확장 첫 탐색: 24개 플랫폼/검색어 작업에서 Instagram 작성자 74명·80개 원문 링크, TikTok 106명·140개 링크, Threads 132명·133개 링크를 발견했다. 원문 확인 및 Laya 선별 후 4개 소셜 식음료 콘텐츠 271건(Instagram 96, TikTok 75, Threads 81, YouTube 19)이 관측 화면에 연결됐다. Threads의 ‘과일 모찌’ 검색 1건은 공개 본문 확인 실패로 기록됐다. 검색 인덱스·공개 첫 페이지의 편향과 누락이 있으며 플랫폼 전체를 빠짐없이 보지 않는다. 공개 캡션·제공된 대본 중심 분석이고 모든 영상의 영상·음성을 읽은 것은 아니다.

참고한 공개 구현: [Instaloader 4.16 공개 페이지 수집](https://github.com/instaloader/instaloader/releases/tag/v4.16), [TikTok 공개 크리에이터 임베드](https://developers.tiktok.com/doc/embed-creator-profiles/), [yt-dlp TikTok 임베드 파서](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/tiktok.py). 필요한 공개 JSON 부분만 독립적인 표준 라이브러리 파서 `mirror/trend_public.py`로 구현했다. yt-dlp는 YouTube에만 사용하며 TikTok의 challenge 처리 경로는 호출하지 않는다.

공식 API를 추가하려면 프로젝트 `.env`에 `social.env.example`의 필요한 값만 설정하고 워커를 다시 시작한다. 기본 공개 수집에는 불필요하다. Instagram은 프로페셔널 계정과 공개 콘텐츠 접근 승인, Threads는 승인된 `threads_keyword_search` 권한이 필요하다. TikTok Display API는 승인한 계정의 영상만 제공한다. 실계정 공식 호출은 미검증이고 모의 응답으로 계약을 검사했다. 토큰을 채팅이나 저장소에 올리지 않는다.

## Decode · Laya 콘텐츠 분석

**콘텐츠 트렌드 → 캠페인별 Decode** 또는 **미디어 대응실 → 🎬 Decode**에서 [The Decode System](https://claude.ai/artifact/CsB8SpVZJ7cnb7VShaJuaB)의 분석 흐름을 사용한다.

1. 기존 수집 소스와 가져올 제목·본문 검색어, 포맷을 지정한다.
2. 기존 `media.db`의 조회수·추천·댓글 데이터(`content`)와 외부 미디어 글(`items`)을 연결한다. 같은 원문이 있으면 조회수 데이터가 있는 자료를 우선한다. 재가져오기는 원래 관측시각을 보존한다.
3. 선택적으로 기존 수집기를 갱신한다. 커뮤니티·뉴스·블루스카이·마스토돈 등 기존 경로를 재사용하며 **Apify를 호출하지 않는다**. 유튜브는 기존 공식 API 키가 필요하다. 필수 소셜 채널 자동 수집과 공개 링크 관측은 콘텐츠 트렌드에서 연결하며, JSON/CSV 가져오기도 지원한다.
4. **Laya 로컬 모델만** 사용해 제목·본문·캡션·대본·화면 자막을 분류한다. Jev·외부 LLM 키나 호출은 필요 없다. 브랜드·포맷·텍스트가 바뀌면 재분류한다.
5. 플랫폼·소스·조회 지표별로 포맷 중앙 조회수 ÷ 전체 중앙 조회수를 비교한다. 썸네일 산점도·포맷 강조·원문 상세·Decode 애니메이션을 제공한다. 5건 미만은 판단 보류다.

영상 파일 URL이 있는 자료는 로컬 Whisper 대본과 RapidOCR 한국어 화면 자막(0·2·4·6초)을 추가할 수 있다. 텍스트 글은 이 단계를 건너뛴다.

```bash
.venv/bin/pip install -r requirements-decode.txt
```

파일 가져오기: JSON 배열 또는 CSV, 최대 20MB/10,000건. 기본 열은 `id, url, creator, caption, views, likes, comments, shares, thumbnail, video_url, transcript, on_screen_text, published`이며 기존 SNS 내보내기 필드도 인식한다.

캠페인·분류·관측 이력은 `data/decode.db`에 보관한다. 기존 원본 테이블과 예전 캠페인 데이터는 삭제하지 않는다. 이전 버전 캠페인은 수집 소스를 다시 선택해 저장한다. 영상 캐시는 `data/decode_media`, 모델은 `data/models/whisper`, `data/models/decode-ocr`에 저장한다. 영상은 개당 150MB·10분 이하를 대상으로 한다.

조회수 미제공 자료는 분류·원문만 보여 주며, `items.engagement`를 조회수로 간주하지 않는다. 캠페인 배수는 게시 시점·계정 규모·광고비를 보정한 인과 효과나 미래 바이럴 확률이 아니다. 0/미제공 좋아요는 로그 차트에서 제외하되 표에는 남긴다. 브랜드 판정은 텍스트 근거이며 로고 검출이 아니다. OCR 네 프레임 사이의 자막은 놓칠 수 있다. 기존 제목 분류 평가의 Laya 정확도는 44.5%로, 캠페인별 검증이 필요하다.

|---|---|---|
| 수집한 SNS 글 97건(예측 보지 않고 1인 라벨, 복수 정답) | 61.9% | 67.0% (전부 중립 71.1%, McNemar p=0.42) |

## 포맷 분석 (`mirror/formats.py`, 미디어 대응실 → 🏆 포맷)
어떤 포맷이 **많이 쓰이나**와 **실제로 터지나**를 가른다. 배수 = 조회수 ÷ 같은 게시판·채널에서 비슷한 때 올라온 글들의 중앙값(규모·게시 시점 보정). 5개 미만 판단 보류, Mann-Whitney + BH, 게시판을 하나씩 빼도 유지될 때만 '터지는 포맷'.

- `python -m mirror.formats collect` · `check`. 유튜브(`YOUTUBE_API_KEY`, 채널별 최근 50편 기준선)는 **실제 호출 미시험**, 릴스·틱톡은 CSV 업로드
- 2026-11-24 실측: 게시판 8곳 1,097건. 분류 정확도(예측 보지 않고 1인 라벨 110건) LLM 84.5% · laya 44.5%('전부 해당 없음' 40.9%) → 기본 분류기는 LLM
- 유의 포맷 5개 중 4개가 인벤 하나에 의존, '썰·사연'(1.14배, n=96)만 유지. 식음료 글은 9건뿐이라 음료 포맷에 대해서는 아무 결론도 낼 수 없음
